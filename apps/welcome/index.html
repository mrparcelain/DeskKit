Guide Make it yours

Welcome to your desktop.

Desk Kit is a web-based desktop template that looks and feels like a computer. Every app opens in its own window, each one is just a folder of HTML, CSS and JavaScript you can edit yourself. You don't need any build tools! Find the source code on GitHub

Apps are folders.

The desktop page doesn't know about any app in advance. When it loads, it reads a list of folders and builds everything from what it finds.

  1. apps/apps.json A list of app folder names. Each one becomes an icon, in this order, 3 per row.
  2. apps/<name>/app.json The app's name, icon and window size, plus which files to load.
  3. index.html · style.css · script.js Loaded the first time you open the app. The HTML goes inside the window, then the script runs.

What's in the project

apps/Every app, one folder each. This is where you'll spend your time.
desktop/index.htmlThe desktop itself: wallpaper, clock and the empty icon grid.
script/desktop.jsLoads apps and runs the windows. Gives apps the Desktop toolkit.
css/desktop.cssWindows, icons and shared design tokens (sizes, spacing, fonts).
developer/A friendly editor for the Music and Photos libraries.
api/Small PHP scripts the editor uses to publish changes and upload images.
ui/ · media/ · fonts/Shared interface images, your wallpaper and logo, and fonts.

On phones

The same page turns into a phone layout when the screen is narrow - try making this browser window thinner. Icons become tabs along the top and each app fills the screen. It switches back as soon as there's room for windows again. The editor at /developer/ stays computer-only.

Because apps are loaded with fetch, the site has to be opened through a web server - your hosting, php -S localhost:8000, or an editor extension like Live Server. Double-clicking desktop/index.html in your file browser won't load the apps.

Make an app in five steps.

We'll make a tiny guestbook called Hello. Swap the name for whatever you're building.

  1. Copy the starter

    Duplicate apps/_starter and rename the copy to apps/hello. Use lowercase letters, numbers and dashes - the folder name is the app's id.

  2. Put it on the desktop

    Add the folder name to apps/apps.json:

    [
  "welcome",
  "music",
  "photos",
  "hello"
]

  3. Name it

    Open apps/hello/app.json and set the name, icon and window size. Sizes use rem (1rem = 16px).

    {
  "name": "Hello",
  "icon": "../../ui/icon/folder.png",
  "window": { "width": "28rem", "height": "20rem" },
  "html": "index.html",
  "styles": ["style.css"],
  "scripts": ["script.js"]
}

  4. Build the window

    Replace apps/hello/index.html with the content of your window - no <html> or <body>, just what goes inside.

    <div class="hello">
  <h1 class="hello-title">Sign my guestbook</h1>
  <form class="hello-form">
    <input class="hello-name" placeholder="Your name" required>
    <button>Sign</button>
  </form>
  <ul class="hello-list"></ul>
</div>

    And style it in style.css. Start class names with the app's name so they can't clash with other apps:

    .hello { padding: var(--space-5); }
.hello-title { font-size: var(--text-xl); margin: 0 0 var(--space-3); }
.hello-list { margin-top: var(--space-4); }

  5. Make it do something

    In script.js, change the id to 'hello'. The function runs once, when the window first opens:

    Desktop.app('hello', ({ body }) => {
  const form = body.querySelector('.hello-form');
  const input = body.querySelector('.hello-name');
  const list = body.querySelector('.hello-list');

  form.addEventListener('submit', (event) => {
    event.preventDefault();
    const item = document.createElement('li');
    item.textContent = `${input.value} was here`;
    list.append(item);
    form.reset();
  });
});

    Reload the desktop and double-click Hello. That's it - you made an app.

Stuck? Open your browser's developer console - the desktop logs a clear message when an app's files can't be found. Full details live in apps/README.md.

What your script gets.

Desktop.app(id, setup) hands your setup function a few helpers. Pick the ones you need: 

Desktop.app('hello', ({ body, url, onOpen, onClose, close, setTitle }) => {
  // ...
});
bodyThe element holding your index.html. Use body.querySelector(...) to find things.
url(path)Full address of a file in your app folder - for fetch(url('data.json')), images or audio made in JS.
onOpen(fn)Run code every time the window opens (the first time too).
onClose(fn)Run code when it closes - pause a video, stop a timer.
close()Close the window from your own button.
setTitle(text)Change the title bar text.

Anywhere on the page

Desktop.open('music')Open or bring an app to the front.
Desktop.close('music')Close an app.
Desktop.createWindow({ title, width, height })An extra window, like the Photos viewer.
Desktop.url('photos', 'photos.json')Address of a file in any app's folder.

Phone layout

On a phone, every app gets a tab and shows its normal index.html full-screen. That's enough for most apps. For a layout made for touch (like Music and Photos), add a "mobile" block to app.json and register a second setup function: 

// app.json
"mobile": {
  "html": "mobile.html",
  "styles": ["mobile.css"],
  "scripts": ["mobile.js"]
}

// mobile.js
Desktop.mobileApp('hello', ({ body, url, onModeChange }) => {
  // same helpers as Desktop.app
});
Desktop.mode'desktop' or 'mobile' right now.
onModeChange(fn)Runs when the page switches layouts - e.g. pause audio that's playing in the other layout.
"mobile": falseIn app.json: hide the app on phones.

Handy extras

  • Add data-image-menu to an element and its images get the right-click menu.
  • Use <div class="app-empty"> for a quick centred "nothing here yet" message.
  • Link straight to an app: desktop/index.html#photos.
  • Load a library from a CDN in app.json: { "src": "https://...", "optional": true }.
  • Design tokens for consistent sizing: --space-1...--space-6, --text-2xs...--text-xl.

Fill the apps with your work.

Music and Photos come with sample content - made-up artists, generated audio loops and placeholder photos - so you can see how everything works. Replace it with your own whenever you're ready.

Open the editor → Add, edit and delete artists, releases, tracks, photo libraries and albums with forms instead of code.
apps/music/music.jsonArtists → releases → tracks (audio link + length).
apps/photos/photos.jsonLibraries → years → albums → photo links.
apps/*/sample/The sample images and audio. Delete these folders once nothing points to them.

Swap the samples for your own

  1. Clear the samples

    In the editor, click Select, tick every row, then More → Delete. Do it in both the Music and Photos sections.

  2. Add your work

    Use the blue Add button. Images can be dropped straight in; audio needs a link to an .mp3 (or similar) file - put files in a folder like media/audio/ and use ../media/audio/song.mp3, or paste a link from an audio host.

  3. Save it for real

    Until you publish, changes only live in your browser. Publish with the API (), or use More → Download and replace the JSON file in the app's folder yourself.

Paths like ../media/... are relative to the desktop/ page, so they work in both the desktop and the editor.

Make it look like you.

WallpaperReplace media/img/default.webp. Visitors can also right-click a photo → Set as Background.
LogoReplace media/svg/logo.svg - it's on the landing page (index.html).
Page title & sharingReplace the YOUR ... HERE placeholders in the <title> and <meta> tags of index.html and desktop/index.html.
Welcome messageThe clock greeting lives in the small script near the top of desktop/index.html.
App orderReorder apps/apps.json. Remove a name to hide that app.
Icons per rowChange --icons-per-row in css/desktop.css (it's 3).
App iconsSet "icon" in an app's app.json. PNG or SVG, square works best.
Overall sizeEverything uses rem, so changing html { font-size } in css/desktop.css scales the whole desktop.

Upload the folder, and you're live.

Desk Kit is plain files, so any web host works. There are two ways to run it.

Any static host
GitHub Pages, Netlify, Neocities...		Everything on the desktop works. To change Music or Photos, edit the JSON (or download it from the editor) and upload it again.
A host with PHP
most shared hosting		Same, plus the editor can Publish changes and upload images straight to your site. See .

  1. Make it yours first

    Replace the sample content, wallpaper, logo and the YOUR ... HERE placeholders in index.html and desktop/index.html.

  2. Upload everything

    Copy the whole project folder to your host (FTP, your host's file manager, or a Git deploy). Visitors start at index.html.

  3. Check it

    Open your site, enter the desktop and open each app. If an app doesn't open, the browser console says which file is missing.

Test on your computer first From the project folder, run php -S localhost:8000 and open http://localhost:8000. This runs the API too, so you can try publishing locally.

Set up publishing.

The api/ folder has two small PHP scripts the editor talks to. Once they have a secret key, Publish saves your changes on the server for every visitor, and images you drop in are uploaded instead of stored in your browser.

api/upload.phpSaves apps/music/music.json or apps/photos/photos.json (keeping a .backup.json of the old one), and uploads images to api/uploads/.
api/delete.phpDeletes an uploaded image.
api/key.envYour secret key. Empty by default, which keeps publishing switched off.
api/.htaccessStops anyone downloading key.env on Apache hosts.

Step by step

  1. Check your host has PHP

    PHP 7.4 or newer with the fileinfo extension (it's on by default almost everywhere). Locally, php -S localhost:8000 is enough.

  2. Make a secret key

    Any long random string of letters and numbers works. This command makes one:

    php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"

    No PHP on your computer? A password manager's generator is fine - skip symbols like " ; = !.

  3. Put it in api/key.env

    Open the file on your server and fill in the empty line at the bottom:

    API_KEY=your-long-random-key

    Don't put a real key in a public Git repository - add it on the server, or keep api/key.env out of the repo.

  4. Let PHP write files

    The server needs permission to write to apps/music/, apps/photos/ and api/ (it creates api/uploads/ itself). On most hosts this just works; if not, set those folders to 755 in your file manager.

  5. Connect the editor

    Open /developer/, click the settings icon (top right) and paste the same key. Tick Remember the key on this device on your own computer only. Leave API endpoint empty unless you moved the api folder.

  6. Publish

    Make a change, press Publish and check the summary. When the status says Up to date, reload the desktop in another browser - everyone sees the new version.

If something goes wrong

"The API key was rejected"The key in Settings doesn't match api/key.env. Check for spaces or a missing character.
"API key not configured"api/key.env is still empty on the server (or wasn't uploaded).
"No API found" / "Couldn't reach the API"The host doesn't run PHP, or the site isn't served over a web server. Use More → Download instead.
"Failed to save JSON"PHP can't write to the app's folder - fix the folder permissions (step 4).
Unauthorized on some hostsA few servers strip the login header. api/.htaccess fixes this on Apache; ask your host about other servers.
Keep it safe Anyone with the key can change your Music and Photos and upload images. If it leaks, put a new key in api/key.env - the old one stops working straight away.
